# Agent 主工作区与工具侧栏设计

- 日期：2026-09-07
- 状态：已确认，进入实施
- 范围：桌面/移动工作区布局、Dockview 面板编排、工具目录、桌宠根层定位

## 目标

主区域永久归 Agent 会话独享。文件、Git 审查、终端、浏览器、子 Agent、Tmux 和运行时监控统一进入右侧工具区；工具区可以隐藏、调整宽度、最大化、浮动、停靠和弹出，隐藏时不能销毁终端、浏览器或文件编辑状态。

左侧会话栏只负责会话与项目导航。桌宠挂到应用根层，可在整个浏览器窗口拖动。

## 视觉与交互原则

视觉基调是安静、紧凑的工作台，不做卡片式仪表盘。

- Agent 是唯一主工作面，顶部直接显示会话标题、所属工作区和运行状态，不再显示 `Agent` 标签。
- 桌面端右侧工具区与 Agent 并排，默认显示，默认占工作区约四成宽度，用户可拖动分隔线调整。
- Agent 组和工具组均提供最大化、浮动/停靠、弹出窗口三个操作。
- 工具侧栏展开/收起是独立操作，在 Agent 组和工具组可见时都能触达。
- 工具标签可以关闭；`+` 打开工具目录并继续添加页面。
- 没有打开工具时，工具区显示文件、Git 审查、终端、浏览器、子 Agent、Tmux、运行时监控的纵向目录，不显示快捷键提示。
- 左侧会话栏顶部只保留收起按钮，移除运行时监控和当前主机标题。
- 移动端一次只显示 Agent 或工具区；工具区以全屏工作面呈现，顶部按钮负责进入和返回，不在窄屏强行并排。
- 所有按钮使用 Lucide 图标和可访问名称；可见文案同步维护中英文。

## Dockview 架构

每个 Host/Project/Thread scope 继续只拥有一个 Dockview 实例，保留现有 keyed scope 生命周期、布局持久化、renderer `always`、浮动和 popout 机制。

桌面布局固定为两个逻辑组：

1. `workspace-agent-group`：只包含 Agent 面板，不允许其他面板拖入。
2. `workspace-tools-group`：包含所有工具面板和永久 `toolHome` 占位面板，不允许 Agent 拖入。

`toolHome` 只负责维持空工具组并渲染工具目录，它的标签在标签栏中隐藏。存在真实工具时显示真实工具标签；最后一个真实工具关闭后自动激活 `toolHome`。

旧的单组持久化布局在恢复后按面板语义归一化：Agent 回到主组，所有非 Agent 面板进入工具组。无法恢复的布局回退到新的双组默认布局，不能出现空白工作区。

工具区显隐独立于 Dockview 序列化布局，按账号和 scope 持久化。桌面默认展开；调用任何工具启动动作时自动展开并激活目标面板。收起使用 Dockview group 可见性，不删除面板或清理领域 store。

移动端沿用相同面板定义和领域状态，但 Agent 组与工具组互斥显示；进入工具区后获得完整可用宽高，返回 Agent 时工具 renderer 保持挂载。

## 面板与真实数据

所有目录动作复用已有真实 store/composable，不生成假面板或假运行状态。

| 工具       | 打开行为                                          | 可用条件                   | 关闭行为                                        |
| ---------- | ------------------------------------------------- | -------------------------- | ----------------------------------------------- |
| 文件       | 标记当前 scope 的 Files 面板为打开并激活          | 已选择会话                 | 只关闭面板，文件 store 保留未保存状态和冲突保护 |
| Git 审查   | 调用现有 review panel store 并激活                | 已选择会话且有工作区根目录 | 调用现有 review close                           |
| 终端       | 调用现有 PTY 启动入口                             | 当前主机支持远端终端       | 调用现有 terminal close                         |
| 浏览器     | 打开真实 URL 输入对话框，提交后创建 preview panel | 当前主机支持浏览器 preview | 调用现有 browser close，并关闭 preview session  |
| 子 Agent   | 激活一个已存在的真实子 Agent 面板                 | 当前会话已有可见子 Agent   | 调用现有 sub-agent close                        |
| Tmux       | 调用现有 Tmux monitor launcher                    | 已存在可扫描主机           | 调用现有 tmux close                             |
| 运行时监控 | 调用现有 host metrics store                       | 已选择主机                 | 调用现有 metrics close                          |

不可用工具显示禁用态和简短原因。工具目录不承担创建假的子 Agent、终端或浏览器会话。

## Agent 顶部信息

Agent 标签渲染器改为会话信息头：

- 主标题使用当前 thread title；没有会话时使用当前项目名或新会话文案。
- 次要信息显示所属工作区。
- 非 idle/completed 阶段显示真实 runtime phase 和状态点。
- 不再在 Agent 内容内部重复渲染 `ThreadChatHeader`，避免双标题和额外横线。

## 工具目录

工具目录拆成可复用组件，供工具空态和 `+` 菜单共享同一份工具定义与动作。

- 大尺寸空态采用纵向列表，图标、名称和可用状态对齐，不使用嵌套卡片。
- `+` 使用紧凑菜单；浏览器项打开现有 URL 对话框。
- 已打开的单例工具再次点击只激活现有面板。
- 多实例工具继续由现有 store 生成唯一 panel id。
- 子 Agent 有多个实例时，目录展示真实实例供选择，而不是任意挑选一个。

## 桌宠

`GatewayPet` 从 `AgentWorkspacePane` 移到登录后的 `app.vue` 根层：

- 覆盖层使用 `fixed inset-0`，边界是整个浏览器 viewport。
- 四边只保留 `0.5rem` 安全间距，移除输入框底部保留区。
- 拖动位置继续按账号保存，窗口缩放后重新约束到 viewport。
- 桌宠覆盖层保持 `pointer-events: none`，只有关闭按钮和拖动手柄接收指针事件，不阻挡 Agent 与工具操作。

## 状态与错误处理

- Files 打开状态和工具侧栏显隐状态存入 `gateway-workspace-layout` 的账号级本地状态，并按 scope 隔离。
- Terminal、Browser、Sub Agent、Tmux、Git review、Host metrics 仍由各自领域 store 作为事实源。
- 工具启动失败继续使用现有错误流和 toast；目录不吞掉错误，也不提供静默 fallback。
- popout 被浏览器拦截时继续使用现有提示。
- 恢复旧布局失败时记录一次控制台错误并加载新默认布局。

## 测试与验收

单元测试覆盖：

- Agent/工具面板分组和默认双组布局。
- Files 与工具侧栏按 scope 的打开、关闭和默认状态。
- 工具目录的可用条件、真实子 Agent 实例和动作目标。

真实 E2E 覆盖：

- Agent 顶部不再显示 `Agent` 标签，只显示会话信息。
- 桌面默认双组，`+` 可打开工具，标签可关闭，最后一个工具关闭后回到目录。
- 收起再展开工具区后终端/浏览器 DOM 状态不被销毁。
- 两组的最大化、浮动/停靠和 popout 可用。
- 左侧顶部只有收起会话栏按钮。
- 移动端在 Agent 与全屏工具区之间切换。
- 桌宠可拖过左侧会话栏，并在刷新和 viewport 缩放后保持合法位置。
- 现有文件、Git、PTY、Browser、Tmux、Host metrics 和 scope 恢复测试继续使用真实后端。

桌面和移动端都必须无重叠、无横向溢出，业务组件不新增固定 `px` 布局。
